# Домашнее задание 1
## Бизнес-функция: бронирование отелей для туроператора

---

### Глоссарий

| Термин | Определение |
| :--- | :--- |
| **Туроператор** | Компания, которая осуществляет деятельность по формированию, продвижению и реализации туристского продукта |
| **Сервис бронирования** | Онлайн-система для поиска и бронирования отелей |
| **Тариф** | Совокупность условий проживания (тип номера, питание, условия отмены) |
| **Ваучер** | Документ, подтверждающий бронирование, содержит уникальный номер заказа |
| **NPS** | Индекс потребительской лояльности (Net Promoter Score) |

### Бизнес-цели

**Миссия:** давать не просто номер в отеле, а готовое, безопасное и выгодное решение для отдыха, которое нельзя получить на других масс-маркет платформах.

**Видение:** стать главным туроператором России, где каждый пользователь может не только забронировать отель за 1 минуту, но и получить персонализированный маршрут, страховку, трансфер и билеты на события с гарантией лучшей цены.

| Приоритет | Цель |
| :--- | :--- |
| **Сервисное превосходство** | Снизить долю пользователей, покидающих сайт после сравнения цен в пользу конкурентов к 31 декабря 2026 года за счёт внедрения программы лояльности с кэшбэком до 10% и "Гарантии лучшей цены". |
| **Сервисное превосходство** | Обеспечить среднее время ответа службы поддержки в чате не более 1 минуты в режиме 24/7. |
| **Покрытие внутреннего туризма** | Достичь NPS на уровне не менее 20 по итогам первого года работы сервиса. |
| **Умный турконструктор** | Запустить функционал "Пакетное бронирование" (отель + трансфер из аэропорта + медицинская страховка и другие комбинации) как единый продукт к 01.12.2026, увеличив средний чек на 20%. |
| **Умный турконструктор** | Внедрить AI-движок для персонализированных рекомендаций отелей и направлений на основе истории поиска, бюджета и предыдущих поездок пользователя с целью повышения конверсии на 15%. |
| **Умный турконструктор** | Интегрировать не менее 50 региональных экскурсионных бюро и поставщиков развлечений (мастер-классы, гастротуры, билеты в музеи и т.д.) для добавления в процесс бронирования к 01.05.2027. |
| **Доверие** | Добиться снижения количества возвратов/отмен бронирований по причине "несоответствие ожиданиям" на 25% к концу 2027 года за счёт внедрения системы честных отзывов с верификацией "реальный гость". |

### User Stories

#### US-01: Поиск и мгновенное бронирование отеля с подтверждением

**Формулировка:** Как клиент туроператора, я хочу найти и забронировать отель в выбранном городе на нужные даты, чтобы получить подтверждение бронирования на email в течение 5 минут без звонка менеджеру.

**Критерии приёмки:**

*   **AC1: Успешный поиск отелей.**
    *   **Дано:** клиент находится на главной странице сервиса.
    *   **Когда:** он вводит город «Сочи», даты заезда 01.07.2026 и выезда 08.07.2026, количество гостей - 2 взрослых.
    *   **Тогда:** система отображает список доступных отелей в Сочи за < 3 секунд, каждый с фото, ценой, рейтингом и кратким описанием.
*   **AC2: Выбор номера и тарифа.**
    *   **Дано:** клиент видит список доступных отелей.
    *   **Когда:** он выбирает отель «Жемчужина» и нажимает «Выбрать номер».
    *   **Тогда:** отображаются доступные типы номеров, их описание, условия питания и политика отмены, а также итоговая стоимость.
*   **AC3: Временная блокировка номера.**
    *   **Дано:** клиент выбрал номер и нажал «Забронировать».
    *   **Когда:** система обрабатывает запрос.
    *   **Тогда:** номер блокируется на 30 минут, клиенту отображается сообщение «Номер забронирован за вами на 30 минут. Оплатите до истечения времени», и запускается обратный таймер.
*   **AC4: Успешная оплата и подтверждение.**
    *   **Дано:** у клиента есть активная блокировка номера, он ввёл корректные данные карты.
    *   **Когда:** клиент нажимает «Оплатить».
    *   **Тогда:** система списывает средства, отображает сообщение «Бронирование подтверждено!», отправляет ваучер с уникальным номером заказа на email в течение 5 минут.
*   **AC5: Истекло время блокировки.**
    *   **Дано:** клиент не оплатил бронирование в течение 30 минут.
    *   **Когда:** таймер достигает 0.
    *   **Тогда:** система автоматически снимает блокировку номера, отображает сообщение «Время бронирования истекло. Номер снова доступен другим клиентам» и предлагает выбрать другой отель.
*   **AC6: Ошибка оплаты.**
    *   **Дано:** клиент ввёл неверные данные карты (недостаточно средств, истёк срок действия).
    *   **Когда:** система пытается обработать платеж.
    *   **Тогда:** отображается сообщение с конкретной причиной ошибки («Недостаточно средств», «Неверный CVV-код» и т.д.), блокировка номера сохраняется, предлагается повторить оплату.

#### US-02: Пакетное бронирование отеля с дополнительными услугами

**Формулировка:** Как клиент туроператора, я хочу забронировать отель вместе с трансфером и страховкой в одном заказе, чтобы не оформлять эти услуги отдельно и сэкономить время.

**Критерии приёмки:**

*   **AC1: Отображение опций «Пакетное бронирование».**
    *   **Дано:** клиент выбрал отель и номер и находится на этапе бронирования.
    *   **Когда:** он видит блок «Дополнительные услуги».
    *   **Тогда:** отображаются опции: «Добавить трансфер из аэропорта», «Добавить медицинскую страховку», «Добавить экскурсию», с указанием стоимости каждой.
*   **AC2: Пересчёт итоговой цены при добавлении опций.**
    *   **Дано:** клиент выбрал отель за 50 000 ₽ на 7 ночей.
    *   **Когда:** он добавляет «Трансфер» за 3 000 ₽ и «Страховку» за 1 500 ₽.
    *   **Тогда:** итоговая сумма пересчитывается автоматически и становится 54 500 ₽ с детализацией: «Отель 50 000 ₽ + Трансфер 3 000 ₽ + Страховка 1 500 ₽».
*   **AC3: Успешное оформление пакета.**
    *   **Дано:** клиент выбрал отель, трансфер и страховку, ввёл данные для трансфера (рейс, время прилёта).
    *   **Когда:** он нажимает «Оплатить пакет» и оплата успешно проходит.
    *   **Тогда:** в одном письме приходят: ваучер на отель, ваучер на трансфер с контактами водителя, полис страхования.
*   **AC4: Изменение состава пакета.**
    *   **Дано:** клиент добавил трансфер и страховку, но передумал брать страховку.
    *   **Когда:** он снимает галочку со «Страховки».
    *   **Тогда:** итоговая цена уменьшается на стоимость страховки, страховка исключается из заказа.
*   **AC5: Частичная отмена пакета.**
    *   **Дано:** клиент оплатил пакет (отель + трансфер + страховка).
    *   **Когда:** он отменяет трансфер в течение 24 часов до вылета (согласно политике отмены).
    *   **Тогда:** деньги за трансфер возвращаются, отель и страховка остаются подтверждёнными.

#### US-03: Персональные рекомендации отелей на основе ИИ

**Формулировка:** Как клиент туроператора, я хочу получать персональные рекомендации отелей, подобранные ИИ на основе моих предпочтений, чтобы быстрее находить подходящие варианты и не тратить время на ручной поиск.

**Критерии приёмки:**

*   **AC1: Отображение рекомендаций на главной странице.**
    *   **Дано:** клиент авторизован в сервисе, у него есть история предыдущих поисков и бронирований.
    *   **Когда:** он открывает главную страницу.
    *   **Тогда:** в блоке «Рекомендации для вас» отображается 5-10 отелей, подобранных на основе его истории: городов, бюджета, типа отелей (семейные/деловые/романтические) и количества звёзд.
*   **AC2: Рекомендации на основе текущего поиска.**
    *   **Дано:** клиент ввёл город «Казань» и даты поездки.
    *   **Когда:** система выполняет поиск и показывает результаты.
    *   **Тогда:** в верхней части списка отображаются 3 отеля с пометкой «ИИ рекомендует».
*   **AC3: Рекомендации при пустой истории.**
    *   **Дано:** клиент впервые пользуется сервисом, история поисков отсутствует.
    *   **Когда:** он открывает главную страницу.
    *   **Тогда:** система отображает рекомендации на основе самых популярных отелей в России (сортировка по рейтингу и количеству бронирований) с пометкой «Популярные отели».
*   **AC4: Возможность скрыть рекомендации.**
    *   **Дано:** клиенту не нравятся рекомендации ИИ.
    *   **Когда:** он нажимает кнопку «Не показывать рекомендации» в блоке.
    *   **Тогда:** блок рекомендаций скрывается до следующего поиска, система запоминает предпочтение.

### Ограничения

#### Функциональные ограничения

| ID | Ограничение |
| :--- | :--- |
| **F-01** | Система НЕ бронирует авиабилеты, ж/д билеты, аренду автомобилей на первом этапе (только отели + сопутствующие услуги: трансфер, страховка). |
| **F-02** | Максимальный срок бронирования — 28 суток, минимальный — 12 часов. |
| **F-03** | Оплата доступна только банковскими картами (Visa/Mastercard/МИР) на первом этапе. |
| **F-04** | Отмена бронирования возможна только в соответствии с выбранным тарифом (бесплатно/платно). |
| **F-05** | Система НЕ поддерживает групповые бронирования (более 5 номеров в одном заказе). |
| **F-06** | ИИ-рекомендации НЕ работают для неавторизованных пользователей (показываются только «Популярные отели»). |

#### Нефункциональные ограничения

| ID | Ограничение | Целевой показатель |
| :--- | :--- | :--- |
| **NF-01** | Производительность (поиск) | Время поиска отелей ≤ 2 секунды (p95). |
| **NF-02** | Производительность (фильтрация/сортировка) | Применение фильтров ≤ 4 секунды. |
| **NF-03** | Производительность (рекомендации ИИ) | Время генерации ИИ-рекомендаций ≤ 3 секунды. |
| **NF-04** | Нагрузка | Система выдерживает 3 000 одновременных пользователей. |
| **NF-05** | Время ответа API поставщиков | Среднее время ответа внешних API отелей ≤ 500 мс. |
| **NF-06** | Безопасность платежей | Все данные карт шифруются (соответствие PCI DSS Level 1). |
| **NF-07** | Персональные данные | Хранение данных граждан РФ на серверах в РФ (соответствие 152-ФЗ). |
| **NF-08** | Отправка ваучера | Ваучер отправляется на email в течение 5 минут после оплаты. |
| **NF-09** | Обновление данных | Не кешировать данные отелей более 30 секунд. |
| **NF-10** | Точность ИИ-рекомендаций | CTR (Click-Through Rate) ≥ 5%. |
| **NF-11** | Поддержка браузеров и мобильных устройств | Chrome, Firefox, Safari, Edge (последние 2 версии); iOS 15+, Android 8+. |
